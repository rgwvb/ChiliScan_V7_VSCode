這個程式是什麼
----------------
ChiliScan 是一個純前端的光譜資料分析工具。使用者匯入辣椒或其他物件的 Excel / CSV
量測資料後，程式會自動配對工作表中的波長欄與光強欄，繪製光譜曲線，並計算指定波段的
波峰、平均、最低強度與有效量測點數。

一般分析在瀏覽器執行。使用者按「儲存目前資料」時，解析後的量測資料與分析結果
會傳送到 Firebase；未按儲存時不會自動上傳光譜。雲端保存的不是原始 Excel / CSV 檔案。

三類衍生吸光度比對實驗版
----------------------
首頁頂端的「三類品質比對」會開啟 `classification.html`。此頁在瀏覽器本機比對新鮮、蟲害、腐爛的衍生吸光度；使用者可自行選擇將資料存至雲端。所有結果均須人工複核，尚未完成獨立驗證。

1. 載入含「新鮮」、「蟲害」與「腐爛」工作表的衍生吸光度參考檔，填入實際資料版本並確認校正方式。每類至少 3 筆、至少 40 個共同波長是程式條件，不是實驗驗證標準。參考資料存入目前瀏覽器；舊雙分類版本必須重新載入。
2. 待測工作表需有「波長」欄，只比對 600–660 nm。使用者須明確選擇待測資料格式及與參考資料一致的校正方式；自動模式不能確認校正來源，故不能用於分類。原始光強需包含標準白欄；若選擇暗訊號校正，還需暗訊號欄。分別計算 `R = 樣本 / 標準白` 或 `R = (樣本 - 暗訊號) / (標準白 - 暗訊號)`，再計算衍生吸光度 `A = -log10(R)`。缺少參考欄或不相容的校正方式不予比對。
3. 只比對 600–660 nm，並只使用參考與待測都有效的共同波長。待測檔每個樣本至少需有 40 個共同有效點。
4. 分別找出三類最近 RMSE，依距離倒數正規化為相對相似度；零距離類別平均分配 100%。這不是準確率或機率。尚未建立「接近」的判定門檻，所有比對結果都需人工複核。留一測試僅是內部測試，尚未完成獨立驗證；結果不得作為食品安全或產品放行依據。

Firebase 個人雲端紀錄（需完成後台設定）
---------------------------------------
網站提供 Google 登入及手動儲存／載入，不會自動上傳。每位授權使用者只能查看
自己的 Firebase 紀錄；資料不會自動與組員的 Android App 共用。
「辣椒工廠」試算表已設為知道連結的人可檢視、不能編輯。完成下方 Google API 設定後，
登入紀錄畫面並連結指定試算表，按「儲存目前資料」會先存 Firebase，再同步至試算表的
「ChiliScan Records」分頁，每個樣本／分析結果以一列可讀摘要呈現；其他人持有連結可檢視，
但不能編輯。完整分析資料仍存 Firebase，不會以編碼內容塞進試算表。
持有連結的人可看到試算表中的樣本名稱、樣本編號、備註及分析摘要，請勿輸入機密資料。
首次連結會要求 Google `drive.file` 授權，並使用 Picker 選擇試算表；程式只接受指定檔案。
若 Sheets 同步失敗，Firebase 紀錄仍保留為待同步；連結試算表後選取紀錄，再按「同步至試算表」
可重試，不會重複新增已寫入的資料列。關閉分頁或登出後需重新連結試算表。
登入狀態保留在目前瀏覽器分頁，關閉分頁或登出後需重新登入。
登入並通過授權後，右上角會出現「量測紀錄」入口；未登入時不顯示。點選入口可
切換至獨立紀錄畫面，返回分析時目前資料會保留；載入紀錄後會返回對應分析畫面。
樣本編號、量測時間、樣本狀態及備註
由使用者選填，並非自動判定；量測時間會一併記錄輸入時的瀏覽器時區。
登出只隱藏紀錄區並清空紀錄欄位；已載入頁面的分析仍留在畫面，分類參考資料仍留在
瀏覽器本機。使用共用電腦時請重新整理頁面，並在分類頁使用「清除本機參考資料」。
示範曲線不可儲存。主分析頁保存解析後的工作表、分析設定與特徵；分類頁保存
重新載入的原始參考檔解析數據、待測數據與比對結果。還原分類紀錄時會重新比對。
雲端不保存原始檔案、工作表公式或 Excel 格式。請另外保管原始檔與備份。
單筆資料上限為約 4.5 MiB 的 UTF-8 JSON；超過時應拆分資料檔。清除瀏覽器本機
參考資料不會刪除雲端紀錄；雲端目前無網頁刪除功能，需由專案管理員處理。

管理員首次設定（不得公開開放所有人讀寫）：
1. 在自己的 Firebase 專案啟用 Authentication 的 Google 登入，並將 GitHub Pages
   網域加入 Authentication 授權網域；本機預覽則使用 http://127.0.0.1:5500，
   並確認相應網域獲授權。登入前也需建立 Cloud Firestore 資料庫。
2. 讓預計授權的成員先以 Google 登入一次，從 Firebase Authentication 的使用者
   清單取得每位成員的 UID。未加入允許清單時，網站會拒絕資料庫讀寫。
3. 檢查現有 Firestore 規則和使用中的其他應用，再由專案擁有者審核 `firestore.rules`。
   將其中的佔位文字換成允許的 UID，使用逗號分隔。若已有其他規則，必須小心合併，
   不要直接覆蓋其他應用的權限。發布後測試授權與未授權帳號。
4. `firestore.rules` 僅允許紀錄擁有者更新 `sheetSyncStatus` 與 `sheetSyncedAt`，
   供同步成功後標記狀態。若合併現有規則，保留此欄位限制，不要放寬其他欄位。
   規則發布並測試成功後，將 `js/cloud.js` 中的 `SECURITY_RULES_VERIFIED` 改為
   `true` 才能啟用雲端讀寫。這個開關不能替代資料庫安全規則；它只防止網站在
   規則尚未確認時意外儲存資料。
5. 在 Google Cloud 專案啟用 Google Sheets API、Google Picker API 與 Google Drive API，
   建立瀏覽器 API key，並將可用 API 限制為這三項。HTTP referrer 限制需包含正式網站
   網域、本機預覽網址 `http://127.0.0.1:5500/*` 與 `http://localhost:5500/*`，
   以及 Picker iframe 所需的 `https://docs.google.com/*`。請依實際部署來源調整正式網域。
   將此 key 填入 `js/cloud.js` 的 `PICKER_API_KEY`。API key 會出現在前端，因此必須設定限制。
   執行程式的 Google 帳號須對指定試算表有編輯權；公開連結設定仍維持「檢視者」。
6. Firebase 免費方案有容量與使用量限制。此功能尚未提供自動備份或工廠等級保障。
   儲存與登入失敗時請查看頁面訊息，不要以為資料已經保存。

Firebase 網頁設定屬於瀏覽器可見的設定；資料保護依賴 Authentication 與 Firestore
安全規則，不能依靠隱藏設定。試算表只以使用者 OAuth 權杖存取；不要將服務帳戶私鑰
或管理員憑證放入前端。試算表只存易讀的樣本／分析摘要欄位；每一筆摘要以紀錄 ID
及項目序號識別，重試時會檢查既有資料，避免重複新增。

執行流程
--------
1. 使用者選擇 Excel / CSV 或拖曳檔案。
2. load() 讀取檔案：
   - CSV：由 parseCsv() 轉成二維陣列。
   - Excel：由 SheetJS 讀取工作表。
3. parseSheet() 或 readSheetSeries() 找出標題列、波長欄及樣本欄。
4. analyze() 或 analyzeCross() 依指定波段建立系列曲線資料。
   - replicateMode 可選「每筆量測」、「自動平均」或「每筆＋平均」。
   - 一般格式可用相同樣本名稱加 1、2、3 標示重複量測。
   - 若每個品項有多組相鄰的「波長＋光強」欄位，程式會依品項標題分組；例如「糯米辣椒一」標題下的三組量測只互相平均，不會與其他品項混合。
   - 平均依相同波長逐點計算；分析狀態會回報偵測到的品項組數與量測筆數。
   - 匯入資料及修改工作表、波長欄、波段或平均方式後，結果會自動更新。
5. feature() 計算每個樣本的波段特徵。
6. render() 更新摘要卡、特徵表、原始數據表與圖例。
7. draw() 使用 Canvas 繪製座標軸、刻度、曲線與滑鼠游標提示。
8. 匯出按鈕呼叫 downloadCsv() 建立並下載 CSV。

專案結構導覽
------------
VS Code 左側檔案總管顯示的是專案原始碼與設定。各資料夾和主要檔案用途如下：

- `.github/workflows/`
  - `pages.yml`：GitHub Actions 部署設定，將網站發布到 GitHub Pages。

- `.vscode/`
  - `launch.json`：VS Code 的啟動設定，提供本機預覽入口。
  - `tasks.json`：VS Code 工作清單，透過 `server.ps1` 啟動本機預覽。

- `css/`
  - `style.css`：首頁的共用外觀、版面、表格與響應式樣式。
  - `classifier.css`：三類比對頁的上傳區、結果卡片與比例顯示樣式。

- `js/`
  - `app.js`：首頁主要功能，包括讀取與分析光譜、繪圖及匯出。
  - `classifier.js`：三類衍生吸光度處理、RMSE 相似度比對、結果呈現及中英文切換；語言選擇會與首頁共用並記住。
  - `language.js`：未由目前頁面載入的舊翻譯工具；首頁由 `app.js` 切換語言，判斷頁由 `classifier.js` 切換語言。
  - `xlsx.full.min.js`：SheetJS 函式庫，用來讀取 Excel 檔案；屬於第三方套件，不是 ChiliScan 的業務邏輯。

- 根目錄主要檔案
  - `index.html`：光譜分析首頁的頁面結構。
  - `classification.html`：三類衍生吸光度比對頁的頁面結構，包含中英文切換按鈕。
  - `README.txt`：本專案的功能、操作方式與部署說明。
  - `server.ps1`：本機 HTTP 預覽伺服器，預設網址為 `http://127.0.0.1:5500/`。
  - `.gitignore`：指定不提交至 Git 的本機參考／待測資料 CSV。

JavaScript主要區塊
-----------------
1. 共用狀態與工具函式
   workbook、rows、headers、series、selected等資料，以及中英文、數值格式與HTML防護。

2. Excel / CSV讀取與工作表解析
   parseCsv()、parseSheet()、readSheetSeries()與sheetToRows()。

3. 單一工作表與跨工作表分析
   analyze()處理單一工作表；analyzeCross()處理多工作表疊加；
   兩者都會依指定起始／結束波長篩選數據。

4. 特徵、表格與圖表
   feature()計算統計值；render()更新頁面；renderRawData()建立逐波長表格；
   draw()繪製座標軸、曲線、平滑值與游標提示。

5. 檔案匯入與示範資料
   load()讀取檔案；demo按鈕載入模擬數據。
   示範數據不代表實際量測結果。

6. CSV匯出
   特徵CSV包含波峰與統計值。
   原始數據CSV包含目前勾選樣本在指定波段內的逐波長數據。

重要資料變數
------------
- workbook：目前載入的 Excel / CSV 工作簿物件。
- headers：目前工作表的欄位名稱。
- rows：目前工作表的數據列。
- widx：使用者選擇的主要波長欄。
- series：分析後產生的曲線資料，每筆包含名稱與波長／強度配對。
- selected：目前勾選要繪製的series索引。
- crossCache：跨工作表解析結果快取。
- hover：圖表游標位置，用於顯示附近數值。
